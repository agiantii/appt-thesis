	\section{研究背景}\label{sec:background}

	幻灯片是表达演讲者想法和便于沟通的重要工具，传统的幻灯片工具如Microsoft PowerPoint和Apple Keynote采用“所见即所得”的编辑方式，
	虽然这种方式在许多地方符合直觉且容易上手，但在排版使用、媒体资源管理、代码展示等方面仍然存在许多不便，
	需要用户花费较多精力在布局排版上，而非内容创作。

	近二十年来，基于Web的轻量化幻灯片工具\cite{raggett2006slidywebppt}逐渐出现在人们的视野，
	如Reveal.js、Marp、Slidev等工具支持用Markdown语法编写幻灯片内容，还可以结合现代Web技术栈实现许多有趣且丰富的交互效果。
	其中，Slidev（slide + dev）作为一个基于Web的幻灯片制作工具，不仅支持Vue语法，而且支持丰富的自定义插件，
	可以让用户以Markdown的形式专注于编写幻灯片的内容，
	并制作出具有交互式演示功能的、高度可自定义的幻灯片\cite{slidevteam2026slidedoc}。

	综合以上背景，作者将设计与开发一个基于Slidev的智能幻灯片协作平台，
	该平台可以让用户专注于内容创作，而非布局排版，
	同时还可以利用AI辅助功能让幻灯片制作更加高效、便捷。

	\section{研究意义}\label{sec:significance}

	% \subsection{实践意义}
	该平台将支持实时协作、权限管理系统、AI辅助功能和简单的版本控制。
	可以让多个用户实时协同编辑同一个幻灯片，提高团队工作效率并减少沟通成本，
	而且通过基于快照的版本管理来避开Git这类专业工具，可以降低非技术用户的使用门槛，不需要很高的学习成本。
	利用加入了Slidev相关知识库的AI，还可以帮助用户快速生成幻灯片大纲并优化内容，让幻灯片创作更高效、更优质，
	并且在探寻大语言模型应用于幻灯片内容生成与优化的过程中，可以摸索出人机协作中比较合适的交互方式。

	\section{研究内容}\label{sec:content}

	% \subsection{实时协作}

	为实现多用户能实时协同编辑幻灯片文档，作者将分析并选择Yjs中合适的数据类型，与CodeMirror编辑器内容绑定。
	同时分析Hocuspocus库构建WebSocket协作服务器的方案以及
	如何利用它提供的生命周期钩子实现文档持久化、文档加载和权限校验。
	而且也需要考虑文档管理、权限校验的流程，并非所有幻灯片创作都需要实时协作，
	为减少性能消耗和提升用户的使用体验，作者将设计合适的文档编辑流程，
	尽可能兼顾性能和功能实现。

	% \subsection{权限管理系统}
	
	同时，本论文需要设计实现一个幻灯片协作平台，幻灯片文档的权限控制类似于
	传统的文档管理系统，对于不同的协作者需要有不同的角色，而不同的角色拥有
	其规定的权限，
	所以需要
	基于JWT认证和RBAC模型，设计一个适合于幻灯片文档协作的权限管理系统，
	让用户使用起来既不会太困难也不会过于简陋，
	避免权限混乱或是使用起来过于不便。
	同时，不仅需要在每个API调用时进行权限校验，也需要在WebSocket连接前选择合理的校验方式。

	% \subsection{AI辅助功能}

	为将AI辅助功能融入幻灯片内容创作，作者将研究用合适的人机交互方式集成大语言模型API，
	而并非只是简单的对话交互，需要考虑如何让大模型生成的内容符合Slidev的Markdown语法以及用户的专业领域要求，
	让生成的内容更加符合用户的实际需求。
	为了减少用户的操作流程和提高创作效率，需要设计合适的快捷键指令和内联编辑器的交互方式，
	让幻灯片制作更加高效和高质。

	% \subsection{版本控制系统}

	考虑到当用户在编辑幻灯片文档时，经常会出现一些错误，需要进行撤销，
	同时有时需要撤销回到较为久远的文档版本。为了降低用户使用的门槛，
	本平台需要实现简单的、基于快照的版本控制，支持自动保存和手动保存、手动创建版本，并提供版本历史查看、内容差异对比和一键回滚操作，让非技术用户更快、更容易上手。
