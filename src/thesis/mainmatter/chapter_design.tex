    \section{用户登录模块设计与实现}
    未登录的用户不会显示平台的工作台界面，必须要登录后才能显示，
    在登录弹窗中，用户需要输入用户名/邮箱、密码、验证码。

    系统首先会校验验证码的正确性，验证码随机为4位字母或数字的组合或是简单的加减数学题。
    后端先利用随机函数选择验证码的类型，
    再使用svgCaptcha库来生成验证码的SVG图片以及对应的验证码文本，并设置验证码有效时间为1分钟。
    前端在弹窗组件挂载时调用GET类型的/captcha/generate接口获取验证码的类型以对应的SVG图片，
    验证时通过POST类型的/captcha/verify接口校验验证码。
    

    在验证码校验通过后，系统会对用户名/邮箱、密码依次进行格式、正确性的校验，
    正确则登录成功，错误则提示用户错误信息。
    后端在HTTP请求到达users.controller前，
    会通过class-validator库提供的@IsString()、@MinLength()、@MaxLength()、@Matches()等装饰器
    对请求体中的用户名/邮箱、密码进行格式校验，
    由于在用户注册时就会保证用户名和邮箱的唯一性，所以用户可以通过用户名/邮箱来登录。
    且注册时的密码会经过bcrypt.hash(password, saltRounds)加密后存入数据库，
    所以登录时需要将用户输入的密码进行bcrypt加密后与数据库中的密码进行比对。
    
    登录成功后，后端会返回一个token，前端将其保存在localStorage中，
    % 后续的每次请求都会带上这个token，后端通过解析token来校验用户的身份和权限。

    slide\_user\_roles表记录用户在特定幻灯片中的角色和权限，
    加载文档时，会校验用户权限，阻止未授权操作。
    幻灯片文档可以设置为公开或私有，当文档设置为私有时，必须要viewer及以上权限的角色才能够访问文档。

    用户登录成功后，前端会将token保存在localStorage中，之后的每次请求都会带上这个token。
    后端通过NestJS Guard机制实现权限校验，先将SlidePermissionGuard全局注入到NestJS，然后由如@RequirePermission(AuthPermissions.READ)的装饰器触发权限校验，未设置该装饰器的接口则会直接放行。
    其中AuthPermissions为enum类型，
    有READ、COMMENT、EDIT、VIEW\_HISTORY、MANAGE、DELETE、VIEW。
    SlidePermissionGuard继承@nestjs/common的CanActivate类，通过canActivate()方法来判断是否校验通过，
    在这个方法内，会先通过reflector获取到@RequirePermission()装饰器中所需要的权限，
    而后通过解析前端传送的token，利用context.switchToHttp().getRequest().user获取上下文中的角色信息，
    若幻灯片公开且该接口需要是查阅权限，则直接放行，对于幻灯片需要评论权限的接口同样如此。
    否则将以上参数传入validatePermission()方法中校验，
    并与装饰器中所声明需要的权限相比对，实现权限校验。

        \subsection{幻灯片文档基础编辑模块设计与实现}
    用户可以在编辑器中编辑幻灯片文档的内容，
    编辑器使用轻量级的编辑器CodeMirror，
    前端通过加入HTML、CSS、Markdown相关的插件，
    实现代码高亮、基础的代码提示等常见编辑器的功能。
    % 而且CodeMirror与React兼容，只需要将编辑器视图挂载到React组件内，
    % 就可以把编辑器的内部状态同步到React。

    前端根据Slidev语法解析幻灯片的文档内容，划分页面大纲，每个大纲只显示部分关键内容，
    点击大纲，会将预览窗口中的<iframe>的src设置为对应页面对应的URL，
    同时通过editorViewRef.current.dispatch()将编辑器跳转到对应位置。

    平台支持用户使用快捷键Ctrl+V来上传图片/视频。
    % 以带有媒体URL的标签的形式插入编辑器，
    以上传视频为例，
    前端添加paste监听事件，
    通过event.clipboardData.items获取剪切板内容，
    而后通过item.type来判断粘贴内容的类型，
    后端会以此对视频的格式、大小先后校验，视频的格式得属于MP4、WebM等常见格式，
    大小应小于100MB，而后上传OSS，
    上传成功后返回对应的URL，
    最终会以<video controls src="\{URL\}"></video>的标签插入编辑器中。

    OSS是阿里云提供的一种可靠、安全的云存储方案，
    本平台的所有图片、视频等资源均交由OSS管理，
    在上传文件至OSS前，需要对OSS的region、accessKeyId、accessKeySecret、bucket等进行配置和加载。

    \subsection{AI辅助创作模块设计与实现}

    本平台接入通义千问官方的Qwen-Plus大模型API，能够方便、高效地生成文本内容和图片素材。
    不仅支持幻灯片文档大纲生成，还支持编辑器内联编辑。
    幻灯片文档大纲生成功能主要是为了帮助用户快速生成幻灯片内容的大纲和基本布局，
    而幻灯片是为了表达演讲者所要呈现的内容的，这个制作过程并非是能够一步到位的。
    内联编辑则是为了在帮助用户在幻灯片文档大纲生成后能够更快、更好地细化、完善幻灯片的细节。
    

   
    
    幻灯片文档大纲生成需要用户在左侧编辑器的工具栏中的幻灯片文档大纲生成面板设置主题、期望页数、其他要求、标题等，
    且只能选择选择平台提供的主题，否则后端无法进行编译，
    且在主题选择弹窗中显示主题的预览图片帮助用户更方便地选择合适的主题。

    新增评论时，前端主要向后端传入slideId、userId、replyId、content等参数，
    对于顶层评论而言，replyId为空，
    新增评论的path字段由回复的目标评论的path和自身id组成，
    而评论的id是自增字段，所以需要先存入新增评论的数据，再构建新增评论的path字段，这两个操作不可中断，
    typeorm提供的this.dataSource.transaction()可以实现数据库的事务，
    作者以此确保评论创建和字段更新这两个操作是一气呵成的。
    同时，在用户有权限评论时，
    新增评论需要检查所评论的幻灯片是否存在、同一幻灯片中是否有所回复的评论等情况，

    删除评论需要用户为评论的发表者或是幻灯片的拥有者。
    由于在新增评论的时候，已经维护了每个评论的path字段，
    所以可以使用如DELETE FROM slide\_comments WHERE path LIKE
    '1-5-\%'的SQL语句即可实现一键删除该评论以及所有子评论，避免相对复杂的逐项删除。
