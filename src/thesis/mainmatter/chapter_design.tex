    \section{前端架构设计}\label{sec:frontend-architecture}

    \subsection{技术栈选择}
    在前端部分，作者主要使用React、CodeMirror和lucide-react。
    React能够高效地渲染用户界面并管理组件状态，让平台在面对频繁交互时也可以流畅响应，
    而且基于组件的方式也很方便地进行逻辑复用，方便系统功能拓展和维护。
    采用CodeMirror这样轻量级的编辑器，它体积小巧、启动时间较短，
    可以支持许多插件，实现代码高亮、代码提示、查找替换等常见编辑器的功能。
    lucide-react把每一个SVG图标都封装成React组件，
    使我们可以像使用普通组件那样以声明式的方式放在界面中。
    % 前端部分，主要选用了以下几种技术：
    % React：比较高效地渲染用户界面和管理状态；
    % CodeMirror 6：轻量的代码编辑器，可以满足本平台的代码编辑需求。
    % lucide-react：将每一个SVG图标都封装成React组件，可以很方便地用组件化开发的方式使用。

    \subsection{实时协作实现}

    本平台的实时协作功能用Yjs库实现。
    先绑定Yjs构建的Y.Doc文档实例到CodeMirror编辑器，
    前端通过@hocuspocus/provider与Hocuspocus服务器建立WebSocket连接，
    后面就可以只需要相互传输增量，实现实时协作。

    \section{数据库设计}\label{sec:database-design}

    \subsection{数据库选型}

    用户、幻灯片和权限等表之间的关联关系较为清晰，存在明确的“多对多”、“一对多”等实体关系，
    适合用MySQL这样的关系型数据库管理，
    不仅管理方便，
    而且运行速度快、安全可靠性强\cite{lan2004mysql,hu2015mysql}。

    % 事务支持：MySQL提供完整的事务支持，确保数据的一致性和完整性；

    \subsubsection{slides 幻灯片表}

    幻灯片表存储每个文档的标题、内容与状态信息。如表\ref{tab:slides}所示。
    parent\_id字段自关联到同表id，实现任意深度的树形结构，根节点的parent\_id为NULL。
    created\_by作为冗余字段（其值等于slide\_spaces表的owner\_id），可在部分查询中减少内联接。

    本平台支持用户拖拽来调整目录树的结构，此时，目录树结构可能会经常变动。
    如果引入物化路径，那么我们每次移动一个节点，都需要更新该节点及其所有子孙节点的path字段，这样会大大增加计算复杂度。
    因此，文档树这边只维护parent\_id字段，移动节点的时候只需要修改该记录的父节点引用。
    删除文档节点时则通过递归遍历依次删除子节点。

    \subsubsection{slide\_comments 评论表}

    评论表通过reply\_id和path字段实现评论的树形结构。
    reply\_id指向父评论id，顶层评论的reply\_id为NULL。
    % path存储从根节点到当前节点的完整路径（如1-5-12），
    % 可以借助LIKE前缀匹配一次性获取子树的所有节点，避免递归查询。

    path字段存储从根节点到当前节点的完整路径字符串，如1-5-12。 评论一旦发布，它的结构就不会再发生变化。
    当新增一条评论时，只需要把父评论的path加上当前评论的id，就能得到该评论的path。 我们可以使用如SELECT * FROM
    slide\_comments WHERE path LIKE '1-5-\%'的SQL查询语句，一次性获取任意评论节点下的所有子孙评论，不需要递归查询；
    删除某条评论及其所有回复时同样也只需要一条如DELETE FROM slide\_comments WHERE path LIKE
    '1-5-\%'的SQL语句，不需要递归删除。
    % 另外，评论操作中最频繁的两个场景，正好是物化路径比较擅长的：
    % 一个是展开某条评论下的所有回复，这时候只需要执行如SELECT * FROM slide\_comments WHERE path LIKE '1-5-\%'这样一条SQL查询，
    % 就可以一次性把整个子树取出来，不用递归；另一个是删除某条评论以及它下面的所有子孙回复，
    % 同样可以通过类似 DELETE FROM slide\_comments WHERE path LIKE '1-5-\%' 的单条语句搞定，
    % 这样就避免了逐节点递归删除带来的多次数据库往返。物化路径用冗余一个 path 字段作为代价，
    % 把子树查询和删除的复杂度从递归所需的 $O(n)$ 次查询降到了常数次。在评论这种结构固定、子树操作又比较频繁的场景下，这个做法的性价比确实很高。

    \subsubsection{实时协作具体实现}
    本平台将幻灯片文档的内容定义为Yjs中的Y.Text类型，并通过y-codemirror.next作为桥梁，
    与CodeMirror编辑器绑定，
    当用户在CodeMirror中编辑内容时，内容的变更（删除、输入等）会立即转换为Yjs的更新操作，
    所有编辑操作通过WebSocket实时广播，每个客户端仅需传输增量的Yjs update，大大降低带宽消耗。
    后端的Hocuspocus服务器负责接收这些更新，并通过CRDT算法自动合并来自不同用户的并发编辑，
    同时持久化到数据库，
    保证文档在各个用户之间是一致的。
    后端Hocuspocus服务器主要通过图\ref{fig:Hocuspocus}所示中的函数实现后端WebSocket的权限校验、文档加载与持久化，
    代码中的注释分别说明了每个钩子内部所实现的功能。
    由于Y.Text为二进制数据，所以在文档加载和持久化的实现中，都需要与文本数据相互转化。

    \subsection{版本控制系统}

    % 平台会定期保存文档内容到数据库，防止数据丢失，
    % 用户也可以自己手动操作，创建版本并添加提交消息，
    % 还能一键回滚到任意历史版本，让操作流程更加简单且直观。
    系统会定期自动保存文档内容防止数据丢失，用户也可以用Ctrl+S手动保存。
    使用Ctrl+Shift+S快捷键或点击版本控制面板里的“创建版本”按钮，手动创建版本并添加提交消息。
    在版本控制面板里可以查看文档的所有历史版本，包括版本号、创建时间、创建者和提交消息。
    选择两个版本进行差异对比，系统会可视化显示内容的添加、删除和修改部分。
    选择一个历史版本，点击“回滚到此版本”，文档内容就会恢复到那个状态，回滚操作会生成一个新的版本记录，不会影响原有的历史版本数据。


    版本历史记录表（slide\_versions）中记录每个幻灯片的历史版本。
    每次自动保存或用户手动创建版本时，都会把当前幻灯片内容（slides.content）的完整副本写入slide\_versions表，
    同时记录提交消息（commit\_msg）、创建者（created\_by）和时间戳（created\_at）。
    slide\_versions通过slide\_id外键关联到slides表，删除幻灯片时，对应的版本记录也会因为外键约束跟着一起删除。
    幻灯片的Markdown源码通常占用存储空间不大，图片这些资源都存储在OSS服务，所以这样直接存储完整副本的方式也是可以接受的，
    同时，也正因为存储的时完整副本，进行回滚和查看历史版本时，不需要进行额外的计算。
    % 这种全量快照方式虽然比增量存储占用更多空间，
    % 但幻灯片内容通常不超过数百KB，
    % 其优势在于回滚和对比操作无需重建内容，
    % 直接读取目标版本即可，实现简单且可靠。

    在前端界面中，通过diff库可视化当前编辑器内容和所选择版本内容的差异，
    差异部分会以删除和新增的样式渲染。如在某行中，原本的内容为“abc”，被修改为“abd”，
    则会以删除“abc”以及新增“abd”的形式渲染。
    如图\ref{fig:version-control-interface}所示。

    \subsection{评论与讨论系统}

    平台里集成评论功能，可以对幻灯片文档内容讨论和反馈，如图\ref{fig:comment-interface}所示。
    评论的树形结构是由评论表的parent\_id和path字段共同实现的，

    新增评论评论时候，前端主要向后端传入slideId、userId、replyId、content等参数，
    其中,对于顶层评论而言，replyId为空，而新增评论的path字段由回复的目标评论的path和自身id组成，
    而评论的id是自增字段，所以需要先存入新增评论的数据，再构建新增评论的path字段，这两个操作不可中断，
    作者使用事务来保证评论创建和字段更新这两个操作是一气呵成的。

    删除评论时，
    由于在新增评论的时候，已经维护了每个评论的path字段，所以可以使用如DELETE FROM slide\_comments WHERE path LIKE
    '1-5-\%'的SQL语句即可实现一键删除该评论以及所有子评论，避免相对复杂的递归删除。
